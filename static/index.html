How it works

The real request flow behind every reply:

  1. 1

    Start a conversation

    The customer speaks through the browser voice call or types in the chat box below.

  2. 2

    Flask processes the request

    The message posts to /api/chat, where input limits and validation apply.

  3. 3

    The assistant answers from real data

    A deterministic router resolves orders from the SQLite database and policies from the sample FAQ, with an optional Gemini layer for intent classification only, off by default. No match? An honest “I’m not sure”, never a fabricated answer.

Frequently asked questions

The honest answers: what works, what depends on your browser, and what is only a demo.

?
Does voice work in every browser?

Speech recognition uses the browser’s built-in Web Speech API and works best in recent Chrome and Edge on desktop. Firefox and many mobile browsers lack support. There the mic is disabled with a friendly note, and text chat still works everywhere.

?
Can I just type instead of speaking?

Yes. Text chat is the primary, guaranteed path. Voice is an enhancement, never a requirement.

?
Is Urdu and Roman Urdu supported?

Typing English, Urdu script (e.g. “میرا آرڈر کہاں ہے”) and Roman Urdu (e.g. “mera order kahan hai”) all work. The assistant detects them. Speaking Urdu is different: browser speech recognition needs an installed ur-PK voice pack, which most desktop browsers don’t have, and Roman Urdu has no speech model at all. Spoken Urdu recognition is therefore unreliable and device-dependent; type it instead.

?
Is the shop data real?

No. Every order, customer name, and policy in this demo is fictional sample data, clearly labelled in the UI and in each response’s source field.

?
Does this place real phone calls?

No. Despite the project name, there is no telephony. The “call” is a simulated conversation using your browser’s microphone and speakers.
